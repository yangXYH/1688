# Chrome 可见自动问答使用手册

插件使用你常用 Chrome 中的 1688 登录状态，完成「关键词搜索 → 选择多家商品 → 授权问答 → 在真实旺旺里自动收发 → 记录筛选依据」。每家供应商保留一个真实聊天标签页，你可以看到操作，也可以直接手动回复。

## 1. 准备环境并启动本机服务

需要 Node.js 20 或更新版本、pnpm，以及 Chrome 116 或更新版本。插件需要本机服务提供问答调度和模型连接；仅安装插件不能独立运行。

首次从本仓库安装，在终端运行：

```powershell
git clone https://github.com/yangXYH/1688.git
cd 1688
pnpm install
pnpm build
pnpm ui
```

已有源码时，在项目目录运行：

```powershell
git pull --ff-only origin main
pnpm install
pnpm build
pnpm ui
```

保持运行 `pnpm ui` 的终端开启。默认服务地址是 `http://127.0.0.1:4173`，安装说明页是 `http://127.0.0.1:4173/extension-install.html`。这些地址仅在本机服务启动后可访问。

## 2. 在常用 Chrome 加载插件

1. 在你准备采购的 Chrome 用户配置中登录 1688。
2. 在地址栏输入 `chrome://extensions`。
3. 打开右上角「开发者模式」，点击「加载已解压的扩展程序」。
4. 选择仓库内的 **`extension` 文件夹**，其中应直接包含 `manifest.json`。例如项目在 `E:\project\1688`，就选择 `E:\project\1688\extension`。
5. 在 Chrome 工具栏的扩展菜单中固定「采货台 · 可见自动问答」，点击插件图标打开侧栏。

也可使用仓库提供的 [插件 ZIP](../outputs/1688-chrome-extension.zip)：先解压，再选择包含 `manifest.json` 的目录。ZIP 只含插件；仍需完成第一节的本机服务安装。自行重新打包可运行 `pnpm extension:pack`。

插件复用当前 Chrome 的登录，不需要导出 Cookie，也不需要为了插件运行 `1688 login`。首次加载使用 Chrome 自己的管理界面；步骤可参照 [Chrome 官方说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)。

## 3. 连接本机服务与模型

在插件侧栏展开「1. 连接本机服务」：

1. 默认端口填写 `4173`。
2. 填写旺旺页面顶部显示的**买家账号**，点击「连接插件」。已有本机采购账号时可留空使用该账号，但必须核对与当前 Chrome 一致。
3. 显示「已连接」后，展开「模型连接设置」，填写接口、模型名称、自己的 API Key 和模型并发数，点击「保存模型设置」。

火山引擎接入示例：

| 配置项 | 示例 |
|---|---|
| 完整 Chat Completions URL | `https://ark.cn-beijing.volces.com/api/plan/v3/chat/completions` |
| 模型名称 | `ark-code-latest`，须确认你的账号具有相应权限 |
| API Key | 使用你自己的密钥，勿写进仓库或分享截图 |
| 模型并发数 | 本程序可设置 1–8，建议先用较小值验证配额 |

示例地址和模型需要与你实际开通的服务匹配；其他提供商也可配置兼容 Chat Completions、支持 JSON 对象输出的接口。模型用于理解供应商回复和推进问题。

密钥只保留在本机服务进程内存，不写入插件包或问答记录。服务重启后需要重新填写；相同接口地址下留空保存会保留当前进程已有密钥。已有记录要求使用原买家账号，其他买家请使用独立会话目录，避免混用历史。

## 4. 从关键词启动多家问答

1. 在侧栏「2. 在 1688 搜索」输入关键词，例如「行李箱20寸」。
2. 设置「本批商品数」，默认 `5`，点击「打开搜索」。程序会打开当前 Chrome 的真实 1688 搜索页并读取商品。
3. 检查商品列表，勾选本批目标。也可以先在 1688 手动完成搜索，再点击「读取当前搜索页」。搜索页必须是当前活动标签页。
4. 在「3. 授权本批问答」选择是否询问资质、是否允许每项最多自动追问一次，展开并查看固定问题与澄清话术。
5. 设置消息上限，核对目标与话术后勾选授权，点击「开始本批自动问答」。改变商品或问答选项后需重新授权。
6. 程序识别商品的卖家账号，并为每家供应商打开真实旺旺标签页。侧栏显示会话进度；点击「打开真实旺旺」可查看实际聊天、输入和发送结果。

问答依次涵盖同款、外销包装、现货、样品和代发、可选资质与报告、专票与票点。明确回复由模型分析并记录依据；图片、文件、含糊回复或缺少可靠消息标识时会停下等待核对。

同一卖家的多个商品会合并或转人工核对，勾选 5 件不保证得到 5 个不同卖家。重新选择已有会话会复用记录，不会直接重发最初问题。搜索结果凭据有效期为两小时，服务重启或结果过期后需重新读取搜索页。

## 5. 并发如何运行

| 项目 | 当前行为 |
|---|---|
| 本批商品数 | 1–100 件，默认 5 件；与模型并发数分别设置 |
| 供应商会话 | 独立保存状态；一家等待回复时，其他家可以继续 |
| 浏览器操作 | 最多两个读取任务并行；实际点击发送保持串行 |
| 模型分析 | 使用 1–8 个工作位，可以同时分析不同供应商 |
| 消息预算 | 包含首次商品链接及后续文本；初次每家通常计两条 |

模型并发上限 8 是本程序的限制，不能据此推断服务商配额或 1688 安全阈值。实际速度还取决于商家回复、页面加载、模型配额和节流。程序使用同一账号，不通过多开账号绕过风控。

## 6. 手动回复、接管与恢复

- 点击「打开真实旺旺」，直接在原生旺旺输入框中回复即可。
- 点击「接管此家」、页面角落的「暂停并接管」，或直接点击/打字，会暂停该家的自动操作；其他会话继续。
- 输入框已有草稿时，程序不会覆盖或自动发送。轮询不会刷新正在编辑的聊天页面。
- 接管后点击「恢复自动」，保留当前问题，重新建立历史基线，等待后续新回复；你的手动对话不会直接被认定为该问题通过。
- 「暂停全部」停止批次；关闭插件侧栏会暂停自动化。关闭某家会话标签页会接管并停止该家的自动操作。
- 保持侧栏和本机服务开启，才会继续自动处理。重新连接、恢复批次由你明确操作，重启不会自动发送。

## 7. 常见问题

| 现象 | 处理方法 |
|---|---|
| 连接不上本机服务 | 确认 `pnpm ui` 正在运行，端口与终端显示一致。插件侧栏连接的是本机 `127.0.0.1`。 |
| 没有读取到搜索结果 | 在 Chrome 手动登录或完成页面验证；让真实商品搜索页处于活动标签，再点击「读取当前搜索页」。 |
| 买家账号不一致 | 核对旺旺顶部账号与插件填写值；已有记录不能直接混用其他买家。 |
| 模型返回 401、403、429 或超时 | 检查密钥、接口、模型权限和配额；配额不足可降低模型并发，处理后再恢复。 |
| 登录失效或出现滑块 | 在当前 Chrome 标签页手动完成，再从插件明确恢复；程序不会绕过验证。 |
| 显示「发送结果待核对」 | 到真实旺旺检查**当前问题文本**。完整发出才选「已确认问题发出」；确认没发出才选「确认未发出」，再核对重新生成的待发送文本。不能仅凭商品链接出现就认定问题已发出。 |
| 已发链接但问题是否发出不清楚 | 先接管会话，在旺旺核对或手动补充，避免盲目重试导致重复消息。 |
| 需要人工核对 | 查看真实回复及附件，使用侧栏的核对操作；有新回复时可重新读取。供应商自述不等于资质已核验。 |
| 更新后行为未变化 | 暂停任务，重启本机服务，在 `chrome://extensions` 点击插件「重新加载」，重新打开侧栏连接；不要在发送途中直接更新。 |

## 8. 数据与验证范围

问答记录默认保存在用户目录的 `.1688/supplier-dialogue.json`，也可由 `BB1688_HOME` 指定独立目录。记录包含私人对话，请自行妥善保管。原工作台在插件模式下隐藏聊天副本，实际回复使用原生旺旺。

插件不读取或导出 Chrome Cookie，不包含下单、付款或站外联系。供应商消息交给你配置的模型分析；筛选结果记录的是供应商声称，证书和商品一致性仍需人工核验。

开发检查：

```powershell
pnpm agent-verify
pnpm exec playwright install chromium
pnpm test:extension
```

浏览器联测使用隔离的 5 家供应商页面和本机模拟模型，验证原生发送、并行分析、手动接管/回复和关闭侧栏暂停，不联系真实商家。真实 1688 改版、账号登录、权限或风控仍需在实际 Chrome 中核对。
